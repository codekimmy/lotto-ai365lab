# Ai365Lab AI 실험 번호: 로직 문서·변경 이력·재검토 규칙

> 로또는 매 회차 독립 추첨입니다. 1장의 1등 확률은 어떤 번호든 1/8,145,060이고, 어떤 로직도 이를 바꾸지 못합니다.
> 이 번호는 **AI 실험·재미용 참고 번호**이며, 우리가 하는 일은 "추첨 전에 공개하고, 무작위 번호와 나란히 채점해 기록을 남기는 것"입니다.

## 1. 운영 원칙

1. **사전 공개**: 직전 회차 결과가 들어오면 다음 회차 5세트를 만들어 저장소에 커밋합니다. 커밋 시각이 추첨 전 공개의 증거입니다.
2. **수정 금지**: 공개한 번호는 고치지 않습니다. 이미 파일이 있으면 엔진이 덮어쓰지 않습니다.
3. **재현 가능**: 시드는 `sha256("Ai365Lab-<버전>-<회차>")`로 고정돼 있어 누가 돌려도 같은 번호가 나옵니다.
4. **무작위 대조군**: 매 회차 시드 고정 완전 무작위 5세트(`random_rival`)도 함께 공개하고 같은 기준으로 채점합니다.
5. **수학적 기대값 병기**: 성적표에는 항상 무작위 5장 기준 기대값(1장당 일치 0.8개, 5등 이상 1장당 약 1/42)을 같이 보여 줍니다.

## 2. 로직 v1.0 (1252회부터 적용)

**번호 점수** (예측 회차 직전까지의 결과만 사용, 45개 번호 각각 표준점수화 후 가중합)

| 지표 | 내용 | 가중치 |
|---|---|---|
| recent50 | 최근 50회 출현 횟수 | 0.35 |
| gap | 마지막 출현 후 쉰 회차 ÷ 기대 간격 7.5 (상한 4) | 0.30 |
| neighbor | 직전 회차 번호의 ±1 이웃(1점), 직전 회차 번호 자체(0.5점) | 0.20 |
| all | 1회부터 전체 출현 횟수 | 0.15 |

**조합 생성**
1. 점수를 `exp(0.6 × 점수)`로 바꿔 가중치로 쓰고, 시드 고정 난수로 6개 조합 30,000개를 뽑습니다.
2. 구조 필터를 통과한 조합만 남깁니다.
   - 합계: 역대 합계 분포 10~90백분위 안
   - 홀:짝 2:4~4:2, 저(1~22):고 2:4~4:2
   - 연속번호 쌍 1개 이하, 같은 번호대(1-9/10-19/20-29/30-39/40-45) 3개 이하
   - 직전 회차와 겹치는 번호 2개 이하
3. 평균 점수 높은 순으로 고르되, 세트끼리 겹치는 번호 2개 이하, 한 번호는 5세트 중 최대 2번까지만 씁니다.

**이 로직이 할 수 없는 것**: 위 지표는 모두 과거 기록의 요약입니다. 추첨기는 과거를 기억하지 않으므로 이 지표들이 다음 번호를 맞힐 확률을 올린다는 근거는 없습니다. 구조 필터는 "역대 당첨번호에 흔한 모양"으로 고르는 것일 뿐, 흔한 모양은 그만큼 조합 수가 많아서 자주 나오는 것입니다.

## 3. 사후 백테스트 (실전 성적 아님)

v1.0을 1152~1251회(100회, 500장)에 거꾸로 적용한 결과 (`data/backtest_v1.0.json`)

| | v1.0 | 무작위 대조군 | 수학적 기대값 |
|---|---|---|---|
| 1장당 평균 일치 | 0.804 | 0.786 | 0.8 |
| 3개 이상 적중(5등 이상) | 10장 | 18장 | 11.92장 |
| 최고 등수 | 4등 2장 | 4등 1장 | |

기대값과의 차이는 표준오차 0.11배로, 무작위와 구별되지 않습니다. 과거에 맞춰 본 결과는 미래 성과를 뜻하지 않습니다.

## 4. 재검토 규칙 (v1.0 공개와 동시에 고정)

- **판단 구간**: 해당 버전 실전 최근 20회(100장)
- **재검토 조건** (하나라도 해당하면 "재검토 필요")
  1. 1장당 평균 일치가 기대값 0.8보다 낮고, 같은 기간 무작위 대조군보다도 낮을 때
  2. 3개 이상 적중 장수가 기대값(약 2.38장)의 절반 미만일 때
- **변경 절차**
  1. 새 버전(`v1.1` 등)을 `aipicks.py`의 `VERSIONS`에 추가하고 `effective_from`을 **아직 공개 안 된 다음 회차**로 둡니다.
  2. 아래 변경 이력에 무엇을, 왜 바꿨는지 적습니다.
  3. 옛 버전 기록은 지우지 않고 성적표에 버전별로 남깁니다.
  4. 로직 변경은 최소 10회 간격. 매주 바꾸면 우연에 맞춰 흔들리기만 합니다.
- 조건에 해당하지 않아도 사람이 바꾸고 싶으면 같은 절차로 바꿀 수 있습니다. 단, 과거 번호를 다시 만들어 성적을 좋게 보이게 하는 일은 하지 않습니다.

## 6. 데이터 출처

- 1순위 `data/manual_results.json` (수동 정정용, 형식: `{"1252": {"date": "2026-11-28", "nums": [..6개..], "bonus": 7}}`)
- 2순위 동행복권 공식 API. GitHub Actions 같은 해외 서버에서는 접속이 막힐 수 있습니다.
- 3순위 공개 미러 [smok95/lotto](https://github.com/smok95/lotto). 미러 README에도 "오류가 있을 수 있다"고 적혀 있으므로, 당첨번호는 동행복권 사이트에서 한 번 더 확인하세요.

## 7. 출력 파일

- `public/latest_picks.json`: 릴스·카드 생성기용 (스키마 `ai365lab.picks/1`)
- `public/scorecard.json`: 전체 성적표
- `blogger/page_ai-picks.html`, `blogger/gadget.html`: 블로그에 붙여넣는 코드. `raw.githubusercontent.com`의 위 JSON을 읽어 화면을 그립니다(GitHub Pages 불필요). 적용 방법은 `blogger/BLOGGER_SETUP.md`
- `data/picks/<회차>.json`: 회차별 공개 번호와 채점 결과 (커밋 이력 = 공개 시각)
